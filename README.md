# Проект: Микросервисная система реализации готовой продукции для кондитера

Данный проект представляет собой симуляцию работы микросервисной архитектуры для автоматизации бизнес-процессов кондитера-самостоятельного предпринимателя.
В рамках проекта реализованы 8 паттернов проектирования (порождающие, структурные, поведенческие), а также симуляция взаимодействия 4 микросервисов.

---

## 1. Реализованные паттерны проектирования

### Порождающие паттерны (Creational)
*Отвечают за процесс создания объектов, скрывая логику создания и делая систему более гибкой.*

1. **Singleton (Одиночка) — `DatabaseConnection`**
    * **Где применяется:** Сервис каталога и рецептов.
    * **Задача:** Гарантирует наличие единственного подключения к базе данных, чтобы не создавать лишние соединения при каждом запросе.
2. **Factory Method (Фабричный метод) — `PaymentProcessor`**
    * **Где применяется:** Сервис оплаты.
    * **Задача:** Создание нужного обработчика платежа (Карта или Наличные) динамически, в зависимости от выбора клиента.

### Структурные паттерны (Structural)
*Отвечают за композицию классов и объектов, помогая организовать их в более крупные структуры и упрощая взаимодействие.*

3. **Adapter (Адаптер) — `Notifier`**
    * **Где применяется:** Сервис заказов и клиентов.
    * **Задача:** Позволяет отправлять уведомления в Telegram и по SMS через единый интерфейс, скрывая различия в API этих сервисов.
4. **Facade (Фасад) — `OrderFacade`**
    * **Где применяется:** API Gateway (связующее звено).
    * **Задача:** Упрощает оформление заказа. Вместо того чтобы вызывать проверку ингредиентов, расчет цены и создание заказа по отдельности, клиент вызывает один метод фасада.
5. **Proxy (Заместитель) — `Recipe`**
    * **Где применяется:** Сервис каталога и рецептов.
    * **Задача:** Кэширование рецептов. При повторном запросе рецепт берется из кэша, что снижает нагрузку на базу данных.

### Поведенческие паттерны (Behavioral)
*Отвечают за взаимодействие между объектами, определяя, как они общаются друг с другом и распределяют обязанности.*

6. **Observer (Наблюдатель) — `OrderSubject`**
    * **Где применяется:** Сервис заказов и клиентов.
    * **Задача:** Автоматическое уведомление клиента и кондитера при изменении статуса заказа (например, «В работе» или «Готов»), чтобы все были в курсе событий.
7. **Strategy (Стратегия) — `PriceStrategy`**
    * **Где применяется:** Сервис заказов.
    * **Задача:** Гибкий расчёт стоимости торта в зависимости от ситуации (обычный заказ, срочный с наценкой, со скидкой), позволяя менять алгоритм расчёта на лету.
8. **Command (Команда) — `OrderCommand`**
    * **Где применяется:** Сервис заказов.
    * **Задача:** Инкапсуляция процесса оформления заказа в виде команды, которую можно выполнить (передать на кухню) или отменить (вернуть продукты на склад).

## 2. Микросервисы

Проект состоит из 4 логических микросервисов:

1. **OrderService (Заказы и клиенты)** — центральный сервис, который принимает заказы, управляет статусами, вызывает остальные сервисы и уведомляет пользователей (использует `OrderFacade` и `OrderSubject`).
2. **CatalogService (Каталог и рецепты)** — отвечает за проверку и списание ингредиентов, а также за получение информации о рецептах (использует `RecipeProxy`).
3. **PaymentService (Оплата)** — принимает запросы на проведение платежей (использует `PaymentFactory`).
4. **ProductionService (Производство и доставка)** — имитирует процесс готовки и организацию доставки заказа.

## 3. Как запустить проект

1. Откройте проект в IntelliJ IDEA.
2. Перейдите в файл `src/main/java/com/example/Main.java`.
3. Нажмите зеленую кнопку **Run** рядом с методом `main`.
4. В консоли появится меню:
    * Пункты **1–8** позволяют изолированно протестировать каждый из реализованных паттернов.
    * Пункт **9** запускает полную симуляцию работы всех 4 микросервисов (от проверки склада до доставки).
